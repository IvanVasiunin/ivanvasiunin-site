# `infra/`

Deployment files (ROADMAP 1.6). Rules: [`.claude/rules/infra-security.md`](../.claude/rules/infra-security.md). Operations: [`docs/RUNBOOK.md`](../docs/RUNBOOK.md).

| File | Purpose |
|---|---|
| `docker-compose.yml` | Services `web` (Caddy + static build), `api` (FastAPI), `db` (Postgres 18 + pgvector) |
| `Caddyfile` | TLS, security headers, compression, caching, `/api/*` proxy with SSE flushing; copied into the `web` image |
| `.env.example` | Compose variables (`SITE_ADDRESS`, `POSTGRES_PASSWORD`, image names and tag); copy to `infra/.env` |

Dockerfiles live next to their apps (`apps/web/Dockerfile`, `apps/api/Dockerfile`) and are built from the repository root. The root `.dockerignore` is an allow-list, so `data/raw/`, `.env` files and `.git` never reach an image.

## Shape

- **Networks.**
  - `web` is on `edge` and is the only service that publishes ports (80, 443, 443/udp).
  - `api` is on `edge` (outbound access for the LLM provider) and `backend`.
  - `db` is on `backend` only: an internal network with no internet and no published ports.
- **Hardening.**
  - `web` and `api` images run as non-root users (UID 10002 / 10001).
  - Their containers are `read_only`, with `no-new-privileges` and all capabilities dropped.
  - `web` binds 80 / 443 as a non-root user through the container-scoped sysctl `net.ipv4.ip_unprivileged_port_start=0`. A file capability on the binary would be stripped by `no-new-privileges`.
  - `db` keeps only the capabilities its entrypoint needs to drop to the `postgres` user.
- **Health checks.**
  - `api` checks `GET /api/health` (it includes the database).
  - `web` checks Caddy's internal endpoint on `127.0.0.1:2020`.
  - `db` uses `pg_isready`.
  - `api` starts once `db` is healthy.
- **Content Security Policy.**
  - The pages carry a hash-based CSP `<meta>` generated by Astro (`security.csp` in `apps/web/astro.config.mjs`).
  - Caddy adds the header-only directives (`frame-ancestors`, `base-uri`, `form-action`, `object-src`) and the other security headers.
- **psycopg.**
  - The image uses pure-Python psycopg with the system `libpq5`, which gets security updates with the base image.
  - `psycopg-binary` (bundled libpq / OpenSSL) is a development-only dependency.

## Run locally

Needs Docker Desktop.

```sh
cp infra/.env.example infra/.env        # set POSTGRES_PASSWORD
docker compose -f infra/docker-compose.yml up --build --wait
node scripts/check-headers.mjs https://localhost
```

Caddy serves `https://localhost` with a certificate from its own local CA; the browser shows a warning.

## Checks

| Command | What it checks |
|---|---|
| `node scripts/check-infra.mjs` | Static, needs only the Docker CLI: ports, internal network for `db`, exact image tags, `APP_ENV=production`, hardening, non-root multi-stage Dockerfiles with health checks, the allow-list `.dockerignore` |
| `node scripts/check-headers.mjs <url>` | Against a running stack: security headers, no `Server` header, page and asset caching, `/api/health` through Caddy |
| CI job `infra` | Both of the above, plus `caddy validate`, the image build, a `docker compose up --wait` smoke test and a non-root check of the built images |
