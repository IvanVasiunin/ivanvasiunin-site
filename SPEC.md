## 1. Goals and audience

### 1.1 Goals
1. Tell visitors who Ivan is: his experience, skills, projects and how he works.
2. Demonstrate AI-engineering skills (RAG, LangChain / LangGraph, LLM APIs, embeddings and their visualization, evals, guardrails) and high-quality markup.
3. Be a portfolio project in its own right: public code, documented architecture and decisions.

### 1.2 Audience
| Audience | Needs | Primary entry |
|---|---|---|
| Recruiters | A fast, skimmable CV; contacts; PDF | `/cv?view=brief`, PDF |
| Hiring managers / engineers | Depth of experience; how the site is built | AI mode, Full CV, GitHub repo |
| People who want to know Ivan as a person | Hobbies, background | AI mode |
| Search engines and link previews | Server-rendered HTML, meta / OG tags, JSON-LD | `/`, `/cv` |

### 1.3 The assistant
- **Name:** Elio.
- An AI assistant **about** Ivan, not an imitation of him. It speaks about Ivan in the **third person** ("Ivan worked…"). Reasons:
  - honesty and EU AI transparency requirements;
  - a model mistake does not read as Ivan's personal statement;
  - it sounds like a recommendation.
- **Tone:** friendly, concrete, neutral persona (no themed character).
- **Language:**
  - the site UI is in English;
  - Elio answers in the language of the question, supporting at least EN, ES, RU and UK;
  - router templates (greeting, refusals) are also localized.

## 2. Modes and URLs

| URL | Mode | Rendering | Notes |
|---|---|---|---|
| `/` | **AI mode** (default) | Server-rendered HTML + React islands (chat, visualization) | Without JS: 1–2 sentences about Ivan, example questions, link to the CV. |
| `/?q=<text>` | AI mode with a prefilled question | Same | The question is placed in the input and focused, **never sent automatically**: this protects the budget from accidental clicks and crawlers. Used by the example questions' no-JS links. |
| `/cv` | **Text mode** (CV), Full view | Static HTML, no framework JS | Without JS, the Full version is shown. |
| `/cv?view=brief` | Text mode, Brief view | Static HTML + small enhancement script | `?view=full` is the default and may be omitted. |
| `/cv/ivan-vasiunin-cv.pdf` | CV as PDF | Generated at build time from `/cv` print styles | Always the Full version. |
| `/privacy` | Privacy notice | Static HTML | Describes chat statistics, masking and retention. |
| `/api/health` | Healthcheck | JSON | — |
| `/api/chat` | Chat endpoint | SSE | See §4. |
| `/data/points.json` | 2D points for the visualization | Static, generated by ingestion | See §4.4. |

### Mode switcher
The two modes are **separate pages with their own URLs**, switched by top-level controls styled as tabs.

**Pattern (decided, Q1):**
- The switcher is a `<nav aria-label="Mode">` with two links, styled as tabs. The active one has `aria-current="page"`. Tab moves between the links; arrow-key navigation is not used.
- Why not WAI-ARIA Tabs: that pattern (`tablist` / `tab` / `tabpanel`) is for panels inside one page. Here each mode is a separate document, so a screen reader would announce tabs whose panels never appear.

Switching between modes uses cross-document View Transitions where supported (progressive enhancement).

## 3. User stories and acceptance criteria

Notation: **US-A** = AI mode, **US-T** = Text mode, **US-X** = cross-cutting.

### 3.1 AI mode

**US-A1. Ask a question and see a streamed answer.**
- Typing a question and pressing **Enter** sends it. **Shift+Enter** inserts a line break.
- The send button is disabled for empty or whitespace-only input and while a response is streaming.
- The answer appears progressively (streamed tokens).
- Screen readers do not hear token-by-token output; the full answer is announced once via `aria-live="polite"` when it finishes.
- On mobile, the input stays visible above the virtual keyboard and messages are not hidden by it.
- The input `font-size` is at least 16 px equivalent (1 rem) so that iOS does not zoom.

**US-A2. Stop a response.**
- While streaming, the send button becomes **Stop**.
- Clicking Stop aborts the request (`AbortController`). The partial answer remains, marked "Stopped".
- The input becomes available again immediately.

**US-A3. Retry.**
- After an error or a stopped answer, a **Retry** button resends the same question.
- Retry is also available on the last completed answer.
- Retrying replaces the previous answer to that question; it does not duplicate it.

**US-A4. Copy an answer.**
- Each completed answer has a **Copy** button that copies the answer as plain text (Markdown source).
- Success is confirmed visually and via `aria-live` ("Copied").

**US-A5. Example questions.**
- Before the first question the chat panel shows four topic cards above the input (Experience, Skills & stack, Projects, This site); each card holds an example question (Ivan, 2026-11-05).
- Clicking one fills the input and focuses it. It does not send. The user presses Enter or Send.
- Examples are also present in the no-JS HTML of `/` as plain text and links.

**US-A6. Empty, loading and error states.**
- **Empty:**
  - a short introduction of Elio;
  - the AI disclosure (US-A10);
  - example questions.
- **Loading:** after send and before the first token, a "thinking" indicator is shown (respects `prefers-reduced-motion`).
- **Error:** a human-readable message by error code (§4.3), with Retry where it makes sense. Rate-limit errors show when to try again. Stack traces and internal details are never shown.

**US-A7. Autoscroll.**
- The message list follows new tokens while the user is at the bottom.
- If the user scrolls up, autoscroll pauses and a "Jump to latest" button appears.
- Autoscroll resumes when the user returns to the bottom.

**US-A8. Sources in answers.**
- Answers that use retrieved context include source references (e.g. "CV — BrainRocket", "Experience notes — Liketelecom").
- References link to the site's own pages where a URL exists, or to the public GitHub README.
- Templated answers (greeting, refusals, "no information") show no sources; for "no information" the `sources` event carries an empty list (§4.2).

**US-A9. Under the hood panel.**
- Under every answer there is a collapsed **Under the hood** toggle (`<button aria-expanded>`), operable by keyboard.
- When expanded, it shows:
  1. the router decision (class);
  2. retrieved sources: title, source type, relevance score and a short snippet (≤ 200 characters);
  3. time per graph step;
  4. tokens (input / cached / output) and the estimated cost in USD.
- It **never** shows the system prompt, prompt templates, model configuration beyond the model name, API keys or internal IDs other than chunk IDs.

**US-A10. AI disclosure.**
- A visible note near the input says: Elio is an AI assistant, answers may be inaccurate, and Ivan is the source of truth. It links to `/privacy`.

**US-A11. Knowledge map.** ([ADR-0012](docs/adr/0012-knowledge-map-canvas-panel.md); Ivan, 2026-11-07)
- On wide screens (`min-width: 80rem`) a framed card "Knowledge map", in the chat panel's style, stands to the right of the chat. Below that width there is no map.
- It shows every knowledge-base chunk as a star on one map: the 2D projection of the embeddings (ADR-0006), rotated to fill the card, Ivan's material on top. The canvas is decoration (`aria-hidden="true"`); its content is text elsewhere.
- Star colour encodes the source type (CV, experience notes, personal facts, GitHub, site docs) using design tokens; site docs are drawn dimmer than Ivan's own material. A legend explains the colours.
- A caption says what the map is ("Each dot is a passage Elio can read. Similar meanings sit close together."); a "What is this?" button opens a short explainer (embeddings, the projection, "area isn't amount").
- At rest nothing moves.

**US-A12. Highlight retrieved points.**
- When a question is sent, the map dims (~0.9 s) and the caption says it is looking.
- When a `sources` event arrives, the matching stars ignite one by one in the neon of their source's colour (~2.2 s each, staggered by rank): a near-white hot core, the colour around it, a halo. Higher relevance means a brighter, slightly larger star; the rest of the map stays dimmed. A camera eases onto the lit stars (~2.6 s).
- The caption says how many passages were read and lists the **Topics**: concepts named in the answer that also occur in the read passages (e.g. BrainRocket · Angular · Mentoring). No names light up on the map itself.
- Hovering a star shows a ring in its colour and a tooltip: the title, the topics it mentions and, if read, "Read for this answer · relevance 0.94". Hovering or focusing a source in the answer shows the same ring and tooltip on its star, and hovering a star marks its source in the answer.
- The highlight stays until the next question. No sources: nothing lights up and the caption says so.
- Reduced motion: the final states appear without animation.

**US-A13. Input limits.**
- Maximum question length, from config (default 500 characters). A live counter appears near the limit, and the input prevents longer text.
- Per-session and per-IP limits: when reached, the user sees a friendly message (§4.3), not a broken UI.

### 3.2 Text mode (CV)

**US-T1. Brief / Full switch.**
- Two buttons with `aria-pressed`: **Brief** and **Full**.
- The choice is reflected in the URL (`?view=brief`) and survives reload and sharing.
- Without JS, the Full version is shown and the switch is hidden (or rendered as two plain links).
- Brief is short enough to skim in under a minute (one screen per job maximum). Full contains every section of the CV.

**US-T2. CV content.**
- Sections:
  - summary;
  - experience (company, title, dates, location, stack, achievements);
  - skills groups;
  - projects (study projects labelled "Study project");
  - education;
  - certifications;
  - languages;
  - contacts: email `ivanvasyunin@gmail.com`, Telegram `@IvanVasiunin`, GitHub `https://github.com/IvanVasiunin`, LinkedIn `https://www.linkedin.com/in/ivan-vasiunin-9967a5132/`.
- **No phone number anywhere.**
- JSON-LD `Person` is embedded, plus meta and OG tags.

**US-T3. "Ask about this" — dropped (Ivan, 2026-11-07).**
- Links from CV entries to AI mode with a prepared question were built and rolled back: sending the reader from the CV to the chat felt redundant. The CV stays self-contained; AI mode is one click away in the mode switcher.
- The `/?q=` prefill itself stays (§2): the example questions use it as their no-JS fallback.

**US-T4. Print and PDF.**
- Printing `/cv` always prints the Full version, without navigation, the mode switcher or backgrounds.
- A **Download PDF** link serves the build-time PDF generated from the same HTML and print styles.

**US-T5. Layout details (progressive enhancement).**
- CSS scroll-driven animations for section reveals or a reading-progress indicator, inside `@supports (animation-timeline: view())`.
- Without support, the content is fully visible and static. Under reduced motion, there is no motion.

### 3.3 Cross-cutting

**US-X1. Theme.**
- Light and dark themes. The default follows `prefers-color-scheme`.
- A manual toggle switches between Light and Dark (no separate "System" option: until the first choice, the default above applies). The choice is stored in `localStorage` and applied before first paint (no flash).
- Without JS, the system preference is used.

**US-X2. Mobile.**
- Works from 360 px wide, in portrait and landscape, with touch.
- Touch targets are at least 44×44 px.
- No hover-only functionality.
- Uses `svh` / `dvh` and safe-area insets.

**US-X3. Privacy notice.**
- `/privacy` explains:
  - what chat statistics are stored;
  - that question texts are masked before tracing and kept for a limited time;
  - that no analytics cookies are set.

## 4. API and SSE contract

The schemas below are normative. Pydantic models in the API (`schemas/`) implement them, and the frontend types are generated from OpenAPI (see [ADR-0001](docs/adr/0001-tech-stack.md)).

### 4.1 `POST /api/chat`

**Request** (`application/json`):

```jsonc
{
  "message": "What did Ivan do at BrainRocket?", // 1..MAX_QUESTION_CHARS (config, default 500), trimmed
  "session_id": "6f1c…",                        // UUID v4 generated by the client, kept in sessionStorage
  "history": [                                   // optional, last N turns (config, default 6), oldest first
    { "role": "user", "content": "…" },
    { "role": "assistant", "content": "…" }
  ]
}
```

**Response:** `text/event-stream`. Every event's `data` is one JSON object with a `type` discriminator. The SSE `event:` field is not used; clients dispatch on `data.type`.

**Event order:**

```
about_ivan:          route → sources → token* → usage → done
no_info (about_ivan, nothing relevant):
                     route → sources (empty list) → token+ (templated) → usage → done
greeting / off_topic
/ injection:         route → token+ (templated) → usage → done
any failure:         … → error   (terminal, no done afterwards)
```

### 4.2 Events

```jsonc
// route — router decision
{ "type": "route",
  "route": "about_ivan" | "greeting" | "off_topic" | "injection",
  "language": "en" }                 // BCP-47 primary tag detected for the question

// sources — retrieved chunks above the relevance threshold, ordered by score desc.
// Empty list = nothing relevant; then a templated "no information" answer follows.
{ "type": "sources",
  "items": [
    { "chunk_id": "cv:brainrocket:3",          // equals the point id in points.json
      "score": 0.83,                            // 0..1, normalized fused relevance
      "source_type": "cv" | "experience" | "personal" | "site_docs" | "github_readme",
      "title": "BrainRocket — Senior Markup Developer",
      "section": "Key stories",
      "url": "/cv#brainrocket",                 // nullable
      "snippet": "Traced a homepage performance problem to CSS masks…" } // ≤ 200 chars
  ] }

// token — next piece of the answer (Markdown)
{ "type": "token", "text": "Ivan " }

// usage — sent once, right before done
{ "type": "usage",
  "nodes": [
    { "name": "input_guard", "ms": 2 },
    { "name": "router", "ms": 310, "model": "gpt-6-luna",
      "input_tokens": 412, "cached_input_tokens": 0, "output_tokens": 18 },
    { "name": "retrieval", "ms": 120, "embedding_tokens": 9 },
    { "name": "relevance_gate", "ms": 1 },
    { "name": "generate", "ms": 1840, "model": "gpt-6.1-terra",
      "input_tokens": 4380, "cached_input_tokens": 1536, "output_tokens": 402 }
  ],
  "total_ms": 2273,
  "estimated_cost_usd": 0.0061 }   // computed from model prices in config

// done — successful end of stream
{ "type": "done",
  "message_id": "b2e0…",            // server-generated UUID
  "finish_reason": "stop" | "length" | "templated" | "no_info" }

// error — terminal; no done follows
{ "type": "error",
  "code": "input_too_long" | "rate_limited" | "session_limit" | "budget_exceeded"
        | "upstream_unavailable" | "timeout" | "internal",
  "message": "Too many questions in a short time.",  // safe, user-facing English text
  "retry_after_s": 30 }             // optional
```

If the client aborts (Stop), the server stops generation and sends nothing more. "Stopped" is a client-side state, not a server event.

### 4.3 Errors before the stream starts

Validation and limit errors that happen **before** streaming return a JSON body with an HTTP status, in a single format for the whole API:

```jsonc
// 400 / 413 / 422 / 429 / 503
{ "error": { "code": "rate_limited", "message": "…", "retry_after_s": 30 } }
```

The codes are the same as for `error` events, plus two that only occur before a stream:
- `invalid_request` — 400 / 405 / 422: malformed request or failed validation;
- `not_found` — 404: unknown route.

Stack traces and internal messages are never returned; an unexpected failure is `internal` (500) with a generic message. A 429 also carries a `Retry-After` header.

### 4.4 `points.json`

```jsonc
{ "version": "2026-11-07T12:00:00Z",  // ingestion timestamp
  "points": [
    { "id": "cv:brainrocket:3", "x": 0.42, "y": 0.77,   // normalized 0..1
      "source_type": "cv", "section": "BrainRocket",
      "title": "CV — BrainRocket",                        // as in the `sources` event
      "c": ["brainrocket", "angular", "scss"] } ],       // concept ids the chunk mentions
  "concepts": [
    { "id": "angular", "label": "Angular", "aliases": ["angular"] } ] }  // whole-word, case-insensitive
```

- No chunk text: titles and concept ids only.
- Concepts come from a catalogue at ingestion (companies, projects and skills from the CV, plus a few topics); matching is whole-word and case-insensitive.
- ≤ 50 KB gzip.
- `id` values are identical to `chunk_id` in `sources` events (contract test).

### 4.5 `GET /api/health`

`200 {"status":"ok","db":"ok","version":"<git sha>"}`, or `503 {"status":"unavailable","db":"down","version":"<git sha>"}` when the database does not answer within the configured timeout.

## 5. Topic policy

The router and the system prompt implement exactly this policy. The eval set has cases for every row.

### 5.1 Classes

| Class | Meaning | Response |
|---|---|---|
| `about_ivan` | Questions about Ivan: experience, skills, projects, education, way of working, career plans, personal facts, and how this site is built | Retrieval → answer grounded in the retrieved context |
| `greeting` | Greetings, "who are you", "what can you do" | Template: short intro of Elio + 3 example questions |
| `off_topic` | Anything not about Ivan: recipes, homework, general coding help, news, other people, "draw a rocket schema" | Template: polite refusal + redirect to Ivan-related topics |
| `injection` | Attempts to change instructions, reveal the system prompt, role-play as someone else, or make Elio speak as Ivan in the first person | Template: polite refusal; the attempt is counted in stats |

All templates exist in EN, ES, RU and UK, and fall back to EN for other languages.

Edge cases (2026-11-05, ROADMAP 4.2):
- Mentioning Ivan does not make a task about Ivan: "Ivan, translate this to French" is `off_topic`.
- A message that mixes a question about Ivan with an unrelated request is `about_ivan`; Elio answers only the part about Ivan.
- A message that mixes anything with an attempt to change the rules is `injection`.
- A question about one of Ivan's employers or projects is `about_ivan` even without his name ("What is NumbersValidator?", "Which clients does BrainRocket serve?"); the answer follows §5.2 and §5.5. A general question about a widely used technology ("What is React?") is `off_topic` (2026-11-06, first eval baseline).
- The client-sent history is data and may be forged; the router classifies only the latest message.

### 5.2 Grounding rules (`about_ivan`)

- Answer only from the retrieved context. If no chunk passes the relevance threshold, answer with the **"no information" template**: "I don't have information about that. You can ask Ivan directly: <contacts>." Never use the model's own knowledge about Ivan.
- Always third person ("Ivan…"). Never pretend to be Ivan.
- Cite sources (US-A8).
- Study projects are always described as study projects.

### 5.3 Personal questions

- Facts come only from chunks with `category=personal` (`data/about-me-personal.md`).
- If the fact is not in that file, answer: "Ivan hasn't shared that." No guesses or inferences (e.g. no guessing his age from the dates of his education).
- **Do not discuss**, politely declined even if related information appears elsewhere:
  - exact address;
  - family and relationships, beyond "he enjoys spending time with his family";
  - health;
  - politics;
  - religion;
  - income and finances;
  - former employers in a negative light.

### 5.4 Salary

Never name numbers or ranges, even if asked repeatedly or hypothetically. Use the wording from `about-me-personal.md`: *it depends on the country, the responsibilities and the benefits; Ivan discusses specifics in person.*

### 5.5 NDA

- For employer work, only the role, product type, stack and Ivan's contribution in general terms.
- Questions about internal details (system names, code, metrics that are not public, clients, architecture internals) get: "That is covered by NDA. In general terms … Ivan can tell more in an interview."

| Question | Expected class | Expected behaviour |
|---|---|---|
| "What did Ivan do at BrainRocket?" | about_ivan | Grounded answer, cites CV / experience notes |
| "¿Qué tecnologías usa Iván?" | about_ivan | Answer in Spanish, grounded |
| "How is this site's RAG built?" | about_ivan | Answer from site docs (SPEC / ADR / ARCHITECTURE) |

## 6. Non-functional requirements

### 6.1 Performance budgets (starting values; adjusted from measurements)

| Metric | Target |
|---|---|
| `/cv`, Lighthouse mobile (Slow 4G, CPU throttling) | LCP < 2.5 s, CLS < 0.1, INP < 200 ms |
| `/cv`, desktop | LCP < 2.0 s |
| `/cv`, Lighthouse mobile scores | ≥ 95 in all four categories |
| JS on `/cv` | ≤ 30 KB gzip (no framework runtime; the Brief / Full and theme scripts only) |
| JS on `/` (AI mode), total including lazy chunks | ≤ 200 KB gzip |
| JS on `/` before the visualization loads | ≤ 150 KB gzip (the visualization loads after idle) |
| `points.json` | ≤ 50 KB gzip |
| `/` LCP, mobile | < 2.5 s (LCP element is the server-rendered intro, not an island) |
| Time to first token, production p50 | < 2 s |
| Long frames during drift and highlight at 6× CPU throttling | Below the threshold defined in TESTING.md |


### 6.2 Mobile
- Widths 360, 390, 768, 1024 and 1440 are tested, in portrait and landscape.
- Touch targets are at least 44×44 px.
- Chat input stays above the keyboard: `visualViewport` resize handling, plus `interactive-widget=resizes-content` where supported. iOS Safari does not support the latter.
- Safe areas: `env(safe-area-inset-*)`. No `100vh`.
- The mode switcher is reachable with one hand.

### 6.3 Weak devices
- **Light visualization mode:** the knowledge map shows its final states without the camera move and the staggered ignition (the map is desktop-only and never moves at rest).
- It is enabled by any of:
  - `navigator.hardwareConcurrency ≤ 4`;
  - `navigator.deviceMemory ≤ 4` (Chromium only);
  - `navigator.connection.saveData`;
  - runtime detection: more than a quarter of an animation's frames longer than 50 ms, judged when an animation of 1 s or more ends (a gap over 1 s, such as a hidden tab, is idle time, not a long frame); from then on for the rest of the visit.

  Thresholds are named constants in `apps/web/src/lib/viz/frames.ts`. A share, not a count: the chat's own rendering of an answer makes a short burst of long frames that must not switch a capable device off.
- The visualization never blocks chat interaction. It is decoration.

### 6.4 Accessibility
- WCAG 2.2 AA.
- axe in e2e on every screen with zero serious or critical violations.
- Semantic landmarks, one `h1` per page, no skipped heading levels.
- Visible `:focus-visible` everywhere. Keyboard access to every control.
- Reduced-motion support everywhere.

### 6.5 Security
- **Secrets:** environment only. `.env` is never committed. gitleaks runs in pre-commit and CI.
- **CORS:** the production domain, plus `localhost` in development.
- **Security headers:** CSP without `unsafe-inline` scripts (hash-based where needed), HSTS, Referrer-Policy, X-Content-Type-Options, Permissions-Policy.
- **Model output:** rendered as sanitized Markdown with no raw HTML (an XSS test exists).
- **Prompt injection:** handled by layered guardrails ([ADR-0004](docs/adr/0004-guardrails.md)).
- **Under the hood:** shows an explicit allow-list of fields only.
- **Database:** never exposed outside the Compose network.

### 6.6 Privacy
- No analytics cookies.
- **Chat statistics:**
  - question counts;
  - router classes;
  - "no information" rate;
  - error counts.
- **Question texts:**
  - stored only masked (emails, phone numbers and URLs redacted);
  - deleted automatically after the retention period in config (default 30 days);
  - sent to Langfuse (EU region) only after masking.
- Full question texts are not written to application logs.
- The question reaches the model provider (OpenAI, or Anthropic when configured) unmasked: the model needs it to answer. Masking is best effort (emails, phone numbers, URLs); names, addresses and nicknames have no pattern. `/privacy` says both.
- Langfuse traces (question, history, retrieved context, answer, all masked) are kept for the Langfuse project's retention, at most 30 days (Hobby plan, ADR-0001).
- IP addresses are used in memory for rate limiting only and are not persisted.

### 6.7 Cost
- **Spend:**
  - a hard spend limit is set on the OpenAI project;
  - every model ID and price lives in config;
  - every answer's estimated cost is computed and summed in stats.
- **Defaults:**
  - templated answers for non-`about_ivan` classes, so the answer model is never called for them;
  - prompt caching: the static prompt prefix comes first.
- **Eval runs:** cost is estimated before each run, and runs happen only with the owner's consent.
